# Codex 社交媒体资料搜集：教程、对比与组合玩法

## 核心结论

Codex 的社媒讨论正在从“CLI 工具”转向“编程 Agent 平台”。有三条明显脉络：

1. **教程化**：中文社区开始出现系统教程，覆盖 Codex CLI、App、Cloud、MCP、GitHub Action、Automation，而不是只讲安装命令。
2. **对比化**：Codex 与 [[concepts/claude-code|Claude Code]] 的比较重点从模型能力转向产品体验、额度、上下文管理、安全边界和团队治理。
3. **组合化**：用户开始把 Codex 嵌入 Claude Code、Ollama、本地知识库和自动化流水线中，形成多 Agent 协作。

## 资料地图

### 教程与入门

- OpenAI Developers 的 Codex CLI 页面提供官方能力边界：本地终端运行、读写代码、运行命令、npm 安装、ChatGPT/API Key 登录、跨平台支持。
- `OpenAI Codex 从入门到精通` 把 Codex 视为多形态系统：CLI、App、Cloud、Chrome、Computer Use、Auto-review、`/goal` 等。
- `AI-Coding-Guide-Zh` 把 Codex 与 Claude Code、OpenClaw 并列成三线教程，强调 Codex App 主线，CLI/Web/SDK/GitHub Action 作为生态补充。
- `Codex CLI 使用教程` 页面显示中文教程供给正在形成，包括公众号文章、博客、教学视频、团队接入和自动化工作流。

### 与 Claude Code 的对比

- 36氪转载的硅星人Pro文章认为，Codex 的优势来自可控沙盒、并行任务、AGENTS.md 项目规则、内置浏览器、插件生态和 Automations；Claude Code 的痛点集中在额度、上下文中断和产品稳定性。
- 少数派文章把 Claude Code 和 Codex 都列为领先 coding agent，但作者更常用 Claude Code 写项目，把 Codex 用于艰难 debug。
- Tom's Guide 的实测认为 Claude Code 更偏即时可用和新手友好，Codex 更偏深度逻辑、数据处理和长期可扩展性。
- X 上 Tom Belfort 的经验是：一个 Claude Code 长时间没修好的 agentic file-editing 项目，Codex 后来在约一小时内修好并加了成本报告。

### 非标准组合方案

- AlphaSignal AI 介绍 `codex-plugin-cc`：在 Claude Code 中触发 Codex，用于 code review、安全审计、bug investigation 和任务委派。
- Ollama 提到 `codex --oss` 可让 Codex CLI 使用 open-weight 模型，这让 Codex 既是产品，也是可替换模型的本地 agent 外壳。
- 宝玉转述的访谈把“造过 Codex 的人每天用 Claude Code”作为案例，提示工具选择并不等于模型阵营站队；关键是产品架构、上下文管理和具体工程任务适配。

## 对当前仓库的启发

- 应建立 `AGENTS.md` 或等价说明，让 Codex 读取仓库结构、PARA 分类、Obsidian 链接规范、Git 同步规则。
- 适合把 Codex 用在“本地知识库维护”任务：资料摄取、索引更新、链接修复、模板生成、Git 提交说明。
- 如果引入 Claude Code/Codex 双工具流程，先限定任务边界：一个负责实现，一个负责审查，避免无限循环。
- 对 X/公众号来源应保存摘要和出处，不全文复制；重要来源进入 `00-收件箱/`，提炼后进入 `05-资源/知识卡片/LLM Wiki/`。

## Open Questions

- `codex-plugin-cc` 的长期稳定性和账号风险尚需验证。
- `codex --oss` 在复杂项目上的质量取决于本地模型能力，不能等同于官方 Codex 模型体验。
- 中文 Codex 教程中有一部分可能是服务商引流页，采用前需要回到官方文档校验。
