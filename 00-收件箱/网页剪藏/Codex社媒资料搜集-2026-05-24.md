## 主题摘录

### 1. 教程类

中文资料正在从零散教程转向系统化手册。`foraka.cn` 和 `AI-Coding-Guide-Zh` 都把 Codex 拆成 CLI、App、Cloud、MCP、GitHub Action、Automation 等多个入口，其中更值得关注的是 Codex App / Cloud / Automations，而不只是 CLI。

### 2. 对比类

社区对比已经不再只问“哪个模型更聪明”，而是在比较：

- 长任务是否容易断
- token / 额度是否可预测
- 是否有稳定的沙盒和审查流程
- 是否能并行派发任务
- 企业环境里是否更容易治理权限

一个常见结论是：Claude Code 更像贴身终端同事，Codex 更像把任务派到可审查沙盒里的工程系统。

### 3. 离奇/组合方案

最有意思的方案是“在 Claude Code 里调用 Codex”。AlphaSignal AI 提到 `codex-plugin-cc` 会在 Claude Code 中增加 `/codex:` 类 slash commands，使用户能让 Claude 写实现，再让 Codex 做 review、安全审计或 bug 调查。这类组合会提升质量，但也可能造成循环调用和额度消耗。

另一个方向是 Ollama 的 `codex --oss`：让 Codex CLI 调用开放权重模型。这更像“Codex 作为工具外壳，模型可替换”的路线。

### 4. 社区信号

中文社区里，Claude Code 教程仍然更多，也更容易卖课；Codex 的讨论正在增加，驱动力主要来自 Claude Code 额度不透明、上下文中断、产品体验争议，以及 Codex 在桌面 App、沙盒、自动化和插件生态上的补齐。
